| 范围 | 上轮结果 |

| 官方基准 `TestGaccodeWorkBuddyReference` | 2 项通过；使用临时测试源码 `internal/provider/gaccode_workbuddy_reference_test.go`，未应用兼容补丁 |

WorkBuddy 的 `_internal.usageOf` 汇总套餐的 `CycleUsedCapacity` /
`CycleTotalCapacity`，返回有周期消费来源的 `amount/limit/unit`。
Go 基准测试覆盖普通窗口的路由、百分比历史以及 WorkBuddy 每日统计的 Provider
限制：无 `span` 或重置字段时，`used` 为 25%、50%、75% 的窗口仍可路由，
并记录剩余比例 75%、50%、25%；不会自动生成绝对余额预测。
`credits_daily` 仅适用于 WorkBuddy Provider，不支持 `gaccode`；
未知的每日统计及余额预测扩展不会自动进入原版宿主。

GACCode 的 `used` 为相对补充基准的余额缺口，`creditCap` 不是累计消费上限。
普通百分比历史裁剪到 0..100，无法保存 22000 / 12000 的超额细节或负余额。
不能机械添加 WorkBuddy 的 `amount/limit/unit` 来伪造消费量；
余额下降也不等于总消费。可选补丁用于绝对余额走势与预计用完时间，
原版百分比走势和路由无需补丁即可启用。

## 已有宿主测试失败

`TestPluginHTTP2TakesTheProxy` 在当前 Bun 1.3.14 环境下失败。
合成 HTTP/2 响应未取得状态码，测试插件用状态码 0 创建 `Response`，
导致 `RangeError` 和宿主退出。

已在未应用任何改动的官方提交副本中单独运行同一测试，得到相同失败。
补丁后的单独复验也得到相同失败。此项不能标记为通过；它不在本次余额功能的修改范围。

最初完整测试还遇到系统 Node 缺少动态库。切换到可用的内置 Node 后，
取消请求等相关测试全部通过，最终只剩上述 HTTP/2 测试失败。
